# n8n-coding-agent-sandbox
Private sandbox repository for n8n exercise 2 coding-agent workflow.

## دکمه ورود
این مخزن شامل یک دکمه ورود است که برای شروع فرایند احراز هویت کاربران در رابط کاربری استفاده می‌شود. هدف از اضافه کردن این دکمه تسهیل ورود کاربر به سیستم و فراهم‌سازی نقطهٔ آغاز برای جریان‌های احراز هویت (مثلاً ریدایرکت به ارائه‌دهندهٔ OAuth یا باز کردن مودال ورود) است.

راهنمای استفاده و رفتار مورد انتظار:
- موقعیت و نمایش
  - دکمه معمولاً در نوار ابزار بالای صفحه یا در صفحهٔ ورود قرار می‌گیرد.
  - متن دکمه به فارسی "ورود" باشد و پس از احراز هویت می‌تواند به نام کاربر یا "خروج" تغییر کند.

- عملکرد کلی
  - با کلیک روی دکمه، فرایند احراز هویت آغاز می‌شود (ریدایرکت به صفحهٔ احراز هویت یا باز شدن مودال). 
  - در صورت موفقیت، اطلاعات کاربر و/یا دسترسی لازم دریافت شده و به صورت امن ذخیره می‌شوند. ذخیره‌سازی توکن‌ها باید با مکانیزم امن (مثلاً کوکی‌های HttpOnly یا مکانیزم امن سرور) انجام شود؛ از نگهداری طولانی‌مدت توکن‌های حساس در localStorage خودداری شود.
  - در صورت خطا، پیام مناسبی به کاربر نمایش داده شود و دکمه مجدداً فعال گردد.

- نمونهٔ سادهٔ پیاده‌سازی (نمونهٔ کلی و غیرحساس):
  - HTML:
    <button id="login-button">ورود</button>
  - JavaScript (نمونهٔ راه‌انداز):
    document.getElementById('login-button').addEventListener('click', () => {
      // شروع فرایند احراز هویت: ریدایرکت یا باز کردن مودال
      // مثال: redirectToAuthProvider();
    });

- نکات دسترسی (Accessibility)
  - برای دکمه از تگ <button> استفاده کنید تا رفتار صفحه‌کلید و دسترسی پیش‌فرض حفظ شود.
  - متن قابل‌فهم و مختصر باشد و در صورت نیاز از aria-label برای توصیف بیشتر استفاده کنید.

- تجربهٔ کاربری (UX)
  - در هنگام انتظار برای تکمیل فرایند، دکمه غیرفعال و یک نشان‌دهندهٔ بارگذاری (spinner) نمایش داده شود.
  - پس از ورود موفق، وضعیت رابط به‌روزرسانی شود تا نشان دهد کاربر وارد شده است (مثلاً نمایش نام کاربر و دکمهٔ خروج).

- برای توسعه‌دهندگان
  - منطق آغاز و تکمیل فرایند احراز هویت در لایهٔ منطقی (مینی-سرویس یا ماژول auth) قرار گیرد تا از تکرار جلوگیری شود.
  - پیاده‌سازی واحدهای تست برای حالات موفق، ناموفق و قطع ارتباط شبکه‌ای داشته باشید.

- تست و ارزیابی
  - تست دستی: کلیک روی دکمه، بررسی جریان ریدایرکت/مودال، بررسی ذخیره‌سازی امن اطلاعات و نمایش پیام مناسب.
  - تست خودکار: شبیه‌سازی کلیک، شبیه‌سازی پاسخ احراز هویت موفق/ناموفق و بررسی تغییر وضعیت UI.

نکتهٔ امنیتی: هیچ‌گاه مقادیر حساس (توکن‌ها، کلیدها و...) را در مخزن یا فایل‌های متنی قرار ندهید؛ مکانیزم‌های مدیریت امن کلید/توکن پروژه را استفاده کنید.
